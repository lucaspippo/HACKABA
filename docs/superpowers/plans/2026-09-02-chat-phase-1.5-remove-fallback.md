# Ángela Chat Phase 1.5 — Remove the Deterministic Fallback (D9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the deterministic keyword router (`_fallback`) from ever silently answering *as if it were Ángela* in production. It becomes an explicit, labeled `LLM_MODE=fake` dev/test/demo path; a missing/bad key in production is a config error with the chat feature flagged off, and a live model-call failure is always an `error` event (already true since Phase 1) — never a quiet degrade.

**Architecture:** `_fallback()` itself is NOT deleted — its ~920 lines are the only deterministic engine PolPilot has and ~10 test files assert its behavior directly (parity, i18n, leak-guarding, numeric stability). What's removed is the *routing decision* that reaches it silently: `responder()` and `stream_response()` currently call `_fallback` whenever `config.model_disponible()` is false, with no distinction between "we're in a demo with no key" and "production is misconfigured." Phase 1.5 makes that distinction explicit via a new `LLM_MODE` env var (mirroring `hackaton-mdq/backend/config.py`'s `cliente_llm()` pattern per the repo's workspace `CLAUDE.md`), gates it so it is structurally unreachable in production, and turns "no model, not in fake mode" into a real error path instead of a fake answer.

**Tech Stack:** FastAPI + Python 3.12 (`backend/`), React 18 + TypeScript (chat layer only, `frontend/src/lib/chat/**`, `frontend/src/components/assistant/**`).

**Spec:** `docs/superpowers/specs/2026-09-02-chat-experience-design.md` — D9 (rationale, the three-row behavior table, and "the one legitimate production use of a deterministic path" caveat) and the "Invariants for future changes" section. Read it before starting. This plan also depends on Phase 1 (landed on `main` via PR #29): protocol v2, `ChatStreamError`, `ErrorState`, and the `_degraded_stream`/`fake_model` notice seam that this plan replaces.

```python
# --- LLM_MODE (D9) -----------------------------------------------------------
# The deterministic keyword router (angela._fallback) is a real dev/test/demo
# capability, but it must never pass itself off as Ángela in production. This
# is the one explicit switch for that: unset (or any value other than "fake")
# means normal behavior (real model when configured, a real error when not);
# "fake" is an opt-in for dev/test/demo, and is refused outright when
# is_production() is true (see assert_llm_mode_safe_for_production, called at
# app startup in main.py's lifespan).
def fake_mode_enabled() -> bool:
    """True only when LLM_MODE=fake (case/whitespace-insensitive) is set."""
    return os.environ.get("LLM_MODE", "").strip().lower() == "fake"


def is_production() -> bool:
    """True on a Render deployment. Render injects RENDER=true into every
    service it runs (see deploy/DEPLOY.md) — this repo has exactly one
    production host, so that is the whole signal."""
    return bool(os.environ.get("RENDER"))


def assert_llm_mode_safe_for_production() -> None:
    """Refuses to let the app boot with LLM_MODE=fake on production. Called
    once at startup (main.py's lifespan), not per-request: a config mistake
    here should fail loudly and immediately, not degrade silently forever."""
    if is_production() and fake_mode_enabled():
        raise RuntimeError(
            "LLM_MODE=fake is set on a production deployment (RENDER=true). "
            "Remove LLM_MODE from this service's environment variables."
        )
```

## Notes for the Phase 2 planner

- `authz.require_feature` / `authz.require_any_feature` (`backend/authz.py:56-82`), backed by `core/perfiles.features_efectivas(username)`, is the established feature-gating pattern — Phase 2's `/api/angela/suggestions` should use `Depends(authz.require_any_feature("alertas", "oportunidades"))`, the same gate `/api/prioridades` already uses, per the spec's D7.
- `_fallback` remains a large, live function used by ~10 test files and reachable via `LLM_MODE=fake`. Phase 2 and later phases must not assume it is gone from the codebase — only that it can no longer activate silently in production.
- The `"unavailable"` `ChatErrorCode` and its `ErrorState` treatment (no retry button) is a reusable pattern for any other "this feature is structurally off, don't offer to retry" case Phase 2's `AskAngela` triggers might need (e.g. if a section's `AskAngela` button should hide itself entirely when chat is unavailable rather than open a doomed panel — worth a design decision in the Phase 2 plan, not assumed here).
